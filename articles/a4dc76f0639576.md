# はじめに

Raspberry Pi 5（BCM2712 / aarch64）を**常時起動の Claude Code 専用機**にする、というのがこの記事の主題です。手元の Mac を閉じても動き続ける Claude Code を Pi 5 上に常駐させ、Remote Control（サーバモード）で外部からいつでも操作できる環境を作ります。

低消費電力で 24 時間つけっぱなしにできる Pi 5 は、常駐させたい agent の置き場所として手頃です。母艦の Mac とは切り離された専用機なので、多少強い権限を与えても隔離された中で完結します。

Claude Code を常駐させるだけなら Mac でも問題なくできます。ただ手元には MacBook Pro しかなく、蓋を閉じてスリープに入ると動作が不安定になってしまいます。常時起動させておける専用機が欲しかった、というのが Raspberry Pi を使う一番の理由です。

土台には **NixOS** を使います。構成をコードで宣言的に管理しておけば、SD カードが飛んでも「同じイメージを焼き直すだけ」で元の状態に戻せるためです。ただし NixOS のイメージは Linux のビルドなので、macOS からそのままでは作れません。そこで **Docker コンテナを Linux ビルダーとして使う** flake を用意し、Apple Silicon の Mac から arm64 ネイティブでイメージをビルドします。

この記事では、その **SD イメージのビルドから、焼いて SSH で入り、Claude Code を remote-control で常駐させるまで**を扱います。

# 全体の流れ

初回インストールは大きく 4 ステップです。

1. flakeファイルを作成する
2. SDカードに焼く前に **SSH 公開鍵を作成**
2. **イメージをビルド**して SD カードへ書き込む
3. **初回起動**してログインする

起動後に実機側で置く設定（起動時のリポジトリ pull 用トークン、AWS 認証情報など）は本記事の後半で概要だけ触れます。

# 前提・必要なもの

- **Mac端末**
- **Docker Desktop**

macOS 上の Nix は `aarch64-darwin` のものしかビルドできません。Pi 5 に焼くのは `aarch64-linux` なので、Linux のビルダーが必要になります。このリポジトリでは Docker コンテナをビルダーとして使います。Apple Silicon なら arm64 ネイティブコンテナになるためエミュレーションは挟まらず、実機同等の速度で動きます。

# 1. flakeファイルの作成

まずは NixOS イメージをビルドするための flake 一式を作ります。ここでは **Pi 5 を起動して SSH で入れるようにする** ための必要最低限のファイルだけを載せます（起動時の pull や Claude 常駐などの追加設定は後半で足します）。

## ディレクトリ構成

```text
raspberrypi-nixos/
├── flake.nix          # エントリポイント。nixpkgs / nixos-hardware を入力にして構成を定義
├── compose.yaml       # aarch64-linux をビルドするための Linux ビルダー（Docker）
├── Taskfile.yml       # ビルド／デプロイのコマンドをまとめる
├── hosts/
│   └── rpi5.nix       # Pi 5 固有の設定（ファームウェア・カーネル・ホスト名）
└── modules/
    ├── common.nix     # 全ボード共通（locale・ネットワーク・SSH・ユーザー）
    ├── sd-image.nix   # SD イメージの作り方（パーティション・圧縮）
    └── ssh-keys.nix   # ログインを許可する SSH 公開鍵
```

Nix は git 管理下のファイルしか見ないので、ファイルを追加したら `git add -A` を忘れないでください。

## flake.nix

構成のエントリポイントです。`nixpkgs`（Pi 5 のブートファイルが入っている `nixos-unstable`）と、Pi 5 用のファームウェア／カーネルを持つ `nixos-hardware` を入力にします。`nixosConfigurations.rpi5` で構成を組み立て、そこから SD イメージ（`packages`）を取り出します。

:::details flake.nix の内容
```nix
# flake.nix
{
  description = "NixOS SD-card images for Raspberry Pi 5";

  inputs = {
    # Pi 5 のブートファイル/サポートは nixos-unstable に入っている。
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    # Pi 5 用のファームウェア + vendor カーネルを持つ。
    nixos-hardware.url = "github:NixOS/nixos-hardware";
  };

  outputs =
    { self, nixpkgs, ... }@inputs:
    let
      inherit (nixpkgs) lib;
      targetSystem = "aarch64-linux";
    in
    {
      nixosConfigurations.rpi5 = lib.nixosSystem {
        specialArgs = { inherit inputs self; };
        modules = [
          ./modules/common.nix
          ./modules/sd-image.nix
          ./hosts/rpi5.nix
        ];
      };

      # `nix build .#rpi5` -> ./result/sd-image/<name>.img.zst
      packages.${targetSystem}.rpi5 =
        self.nixosConfigurations.rpi5.config.system.build.sdImage;
    };
}
```
:::

## modules/common.nix

どのボードでも共通する土台です。ここでは **起動して SSH で入れる** ために必要な最低限だけを置きます（locale・ネットワーク・公開鍵のみの SSH・`nixos` ユーザー）。

:::details modules/common.nix の内容
```nix
# modules/common.nix
{ lib, pkgs, ... }:

let
  authorizedKeys = import ./ssh-keys.nix;
in
{
  # このリポジトリの対象ボードはすべて 64-bit ARM。
  nixpkgs.hostPlatform = "aarch64-linux";

  time.timeZone = "Asia/Tokyo";
  i18n.defaultLocale = "ja_JP.UTF-8";

  networking.useDHCP = lib.mkDefault true;
  networking.firewall.allowedTCPPorts = [ 22 ];

  # <hostname>.local（rpi5.local）で引けるようにする（mDNS）。
  services.avahi = {
    enable = true;
    nssmdns4 = true;
    publish = {
      enable = true;
      addresses = true;
      workstation = true;
    };
  };

  # Broadcom チップの Wi-Fi / Bluetooth ファームウェア。
  hardware.enableRedistributableFirmware = true;

  # SSH は公開鍵認証のみ（パスワード認証は無効）。
  services.openssh = {
    enable = true;
    settings = {
      PasswordAuthentication = false;
      KbdInteractiveAuthentication = false;
    };
  };

  users.users.nixos = {
    isNormalUser = true;
    extraGroups = [ "wheel" ];
    openssh.authorizedKeys.keys = authorizedKeys;
    # シリアルコンソール用の初期パスワード（SSH はパスワード無効）。
    initialPassword = "nixos";
  };

  security.sudo.wheelNeedsPassword = true;

  # ssh-keys.nix が空ならビルド時に警告する。
  warnings = lib.optional (authorizedKeys == [ ]) ''
    modules/ssh-keys.nix is empty: this image has no SSH key installed.
  '';

  nix.settings.experimental-features = [
    "nix-command"
    "flakes"
  ];

  environment.systemPackages = with pkgs; [
    vim
    git
    go-task
  ];

  # 初回インストール時のリリースに固定する（アップグレードでも上げない）。
  system.stateVersion = "26.05";
}
```
:::

## modules/sd-image.nix

SD イメージの作り方を決めます。汎用の `sd-image-aarch64` プロファイルを土台に、firmware パーティションを広げて `.img.zst` で圧縮出力します。

:::details modules/sd-image.nix の内容
```nix
# modules/sd-image.nix
{ lib, modulesPath, ... }:

{
  imports = [ "${modulesPath}/installer/sd-card/sd-image-aarch64.nix" ];

  sdImage = {
    # overlay や U-Boot を積むと既定の 30 MB では足りない。
    firmwareSize = 128;
    # 初回起動時に root パーティションをカード全体まで広げる。
    expandOnBoot = true;
    # .img.zst で出力する（焼く前に zstd -d する）。
    compressImage = true;
  };

  # SD カードでは使わない ZFS を外す（out-of-tree で重い）。
  boot.supportedFilesystems.zfs = lib.mkForce false;
}
```
:::

## modules/ssh-keys.nix

ログインを許可する公開鍵のリストです。**パスワード認証は無効なので、ここが空だとシリアルコンソールからしか入れなくなります。** 中身は次の章で作った鍵に差し替えます。

:::details modules/ssh-keys.nix の内容
```nix

  # "ssh-ed25519 AAAAC3Nza... you@example.com"

```

## hosts/rpi5.nix

Pi 5 固有の設定です。ここがこの記事で一番ハマりやすいところで、**vendor カーネル + vendor DTB** に揃えるのがポイントです。これを外すと `bcm2712-rpi-5-b.dtb not found` で起動できなかったり、thermal/ファンが立ち上がらなかったりします。

:::details hosts/rpi5.nix の内容
```nix
# hosts/rpi5.nix
{ inputs, lib, ... }:

{
  # nixos-hardware の pi5 モジュールで Pi 5 用ファームウェア + U-Boot +
  # BCM2712 の device tree + vendor カーネル (linux-rpi) を入れる。
  # これが無いと bcm2712-rpi-5-b.dtb not found で止まる。
  imports = [ inputs.nixos-hardware.nixosModules.raspberry-pi-5 ];

  # U-Boot を firmware パーティションに入れてチェインロードさせる。
  # これが無いと extlinux.conf を読めずカーネルを起動できない。
  hardware.raspberry-pi.firmware.uboot.enable = true;

  # vendor カーネルに無いモジュールを initrd 候補から外す。
  # 残すと modules-shrunk 段階で FATAL: Module not found で落ちる。
  hardware.enableAllHardware = lib.mkForce false;
  boot.initrd.systemd.enable = lib.mkForce false;

  networking.hostName = "rpi5";

  # -> out/nixos-sd-image-rpi5.img.zst
  image.baseName = "nixos-sd-image-rpi5";

  # 圧縮スワップ。
  zramSwap.enable = true;
}
```
:::

## ビルド用のファイル（compose.yaml / Taskfile.yml）

macOS は `aarch64-linux` を直接ビルドできないので、Docker コンテナを Linux ビルダーとして使います。`compose.yaml` でビルダーを定義し、`Taskfile.yml` でその中の `nix build` を呼び出します。

:::details compose.yaml の内容
```yaml
# compose.yaml
name: raspberrypi-nixos

services:
  builder:
    image: nixos/nix:2.35.1
    platform: linux/arm64
    working_dir: /workspace
    volumes:
      - .:/workspace
      # /nix を named volume に載せ、2 回目以降の再ダウンロードを防ぐ。
      - nix-store:/nix
    environment:
      NIX_CONFIG: |
        experimental-features = nix-command flakes
        max-jobs = auto
        cores = 0
        sandbox = false
        keep-outputs = true
    command: ["sleep", "infinity"]

volumes:
  nix-store:
```
:::

:::details Taskfile.yml の内容
```yaml
# Taskfile.yml
version: "3"

vars:
  RUN: docker compose run --rm builder

tasks:
  build-rpi5:
    desc: Build the Raspberry Pi 5 SD image into out/
    cmds:
      - >-
        {{.RUN}} sh -eu -c
        'nix build ".#rpi5" --out-link "/tmp/result-rpi5" --print-build-logs;
        mkdir -p /workspace/out;
        install -m 0644 "/tmp/result-rpi5"/sd-image/* /workspace/out/'

  switch-rpi5:
    desc: 'Deploy the config to a running Pi over SSH (usage: task switch-rpi5 IP=<ip>)'
    requires:
      vars: [IP]
    cmds:
      # Pi 5 自身がビルドと適用を行い、Mac は指示を出すだけ。
      - >-
        nix run nixpkgs#nixos-rebuild -- switch
        --flake ".#rpi5"
        --target-host "nixos@{{.IP}}"
        --build-host  "nixos@{{.IP}}"
        --sudo
        --ask-elevate-password
```
:::

これで flake 一式がそろいました。次の章で SSH 公開鍵を仕込んでからビルドします。

# 1. SSH 鍵を入れる（イメージビルド前にやること）


`modules/ssh-keys.nix` に公開鍵を書きます。空のままだとビルド時に警告が出て、シリアルコンソールからしか入れないイメージになります。

```console
$ ssh-keygen -t ed25519 -C "$(whoami)@$(hostname)"
$ cat ~/.ssh/id_ed25519.pub
```

```nix
# modules/ssh-keys.nix
[
  "ssh-ed25519 AAAAC3Nza... you@example.com"
]
```

鍵を書き換えたら、イメージをビルドします。

:::message alert
flake は git 管理下のファイルしか見ません。新しくファイルを追加したら `git add -A` してからビルドしてください（未追跡ファイルがあると警告が出て無視されます）。
:::

# 2. イメージのビルド

`out/` に SD イメージ（`.img.zst`）を生成します。

```shell
$ task build-rpi5

out/nixos-sd-image-rpi5.img.zst
```

# 3. SD カードへの書き込み（macOS）

1. カードを挿してデバイス名を確認する。**間違えると別のディスクを破壊します。**

```shell
$ diskutil list

/dev/disk0 (internal, physical):
...(省略)

/dev/disk3 (synthesized):
...(省略)

# これがSDカード
/dev/disk4 (internal, physical):
   #:                       TYPE NAME                    SIZE       IDENTIFIER
   0:     FDisk_partition_scheme                        *31.0 GB    disk4
   1:             Windows_FAT_32 NO NAME                 31.0 GB    disk4s1
```

2. SDカードをアンマウントする（イジェクトではない）。

```shell
$ diskutil unmountDisk /dev/disk4

Unmount of all volumes on disk4 was successful
```

3. 展開しながら書き込む。`/dev/rdiskN`（`r` 付き raw device）のほうが桁違いに速いです。

パスワード入力後、進捗などは出ないのでちょっと不安になります。7分くらいで終わりました。

```shell
$ zstd -dc out/nixos-sd-image-rpi5.img.zst | sudo dd of=/dev/rdisk4 bs=4m
Password:
0+84191 records in
1289+1 records out
8309010432 bytes transferred in 418.063607 secs (19874991 bytes/sec)
```




4. 終わったら取り出します

```shell
$ diskutil eject /dev/disk4
```

ルートパーティションは初回起動時に自動でカード全体まで拡張されます。

# 4. 初回起動と SSH 接続

- ホスト名: `rpi5`
- ユーザー: `nixos`（`wheel` 所属）
- SSH: 公開鍵のみ。**パスワード認証は無効**
- シリアルコンソール／ローカルログイン用の初期パスワード: `nixos`

SD カードを挿して電源を入れ、ネットワークにつながったら Mac から SSH で入ります。

```shell
$ ssh nixos@rpi5.local
```

これでSDカードへnixOSのインストールは完了です。

## ファンの認識確認

起動後、公式ケースのファンが認識され温度に応じて回っているかを確認します。Raspberry Pi 5 のファンは温度連動（thermal cooling device）として扱われ、温度が上がると段階的に回転数が上がります。

```shell
# 温度と、今どのレベルで回そうとしているか
$ cat /sys/class/thermal/thermal_zone0/temp        # ミリ℃（例: 45000 = 45℃）
$ cat /sys/class/thermal/cooling_device0/cur_state  # 現在のファン段（0=停止）
$ cat /sys/class/thermal/cooling_device0/max_state  # 最大段
```

`cur_state` が `0` のときはファンが停止しています（低温時は正常）。負荷をかけて温度を上げると段が上がっていくことを確認できます。


# 起動後の設定（概要）

ここから先は実機側に秘密情報を置いていきます。方針は共通で、**PAT やアクセスキーは Nix store にも git 履歴にも入れず、実機のファイルに置く**（store は誰でも読めるうえ、イメージは共有物のため）というものです。詳細は別記事に譲り、ここでは概要だけ示します。

## 起動時のリポジトリ pull

`hosts/rpi5.nix` の `services.gitPullOnBoot.repos` に列挙したリポジトリを、起動時にホーム直下（`/home/nixos/<repo>`）へ clone / pull します。未 clone なら clone、既にあれば `pull --ff-only` でリモートに追従します。認証は GitHub の fine-grained PAT を実機の `/etc/gitpull-token` に置いて使います（全リポジトリ共通の 1 本）。

```shell
$ printf '%s' 'github_pat_xxxx' | sudo install -o nixos -g users -m 600 /dev/stdin /etc/gitpull-token
```

上記コマンド実行後に`$ sudo reboot`で再起動します。

なお、この pull の対象には後述の [AI-DLC Workflows](https://github.com/awslabs/aidlc-workflows)（`aidlc-workflows` の `v2` ブランチ・public）も含めており、起動時にホーム直下へ置かれるようにしています。

## AWS 認証情報

アクセスキーは実機の `~/.aws/credentials` に手動で置きます。region などの非秘密の設定だけは宣言的に管理し、起動時に `~/.aws/config` へ置かれます。

## Claude Code を常駐させる

`services.claudeOnBoot`（実体は `modules/claude-remote-control-service.nix`）で、`claude remote-control`（サーバモード）を `nixos` ユーザーで動かす systemd サービスを定義しています。認証は実機の `~/.claude` を使う前提です。

このモジュールを使うには、前半で作った `flake.nix` の `modules` に `./modules/claude-remote-control-service.nix` を足し、`hosts/rpi5.nix` で `services.claudeOnBoot.enable = true;` を有効にします。

このサービス定義には、headless（TTY なし）環境ならではの工夫がいくつか入っています。

- **擬似 TTY 経由で起動する**: TTY が無いと `claude` が非対話（`--print`）と誤判定して stdin を待ってしまうため、`util-linux` の `script` で擬似 TTY を割り当てて対話モードで起動させています。
- **時刻同期を待ってから起動する**: RTC の無い Pi は起動直後の時計がズレており、その状態で TLS 接続すると `CERT_NOT_YET_VALID` で失敗します。`ExecStartPre` で timesyncd の同期完了（`/run/systemd/timesync/synchronized`）を待ってから `claude` を起動します。
- **`claude` は system プロファイルの実体を使う**: `/run/current-system/sw/bin/claude` を指すことで、対話ログイン時の `claude`（認証状態 `~/.claude`）と同一実体にそろえています。

:::details modules/claude-remote-control-service.nix の内容
```nix
# modules/claude-remote-control-service.nix
{
  config,
  lib,
  pkgs,
  ...
}:

let
  cfg = config.services.claudeOnBoot;

  # TTY の無い環境（systemd）だと claude は非対話（--print）と誤判定して stdin を
  # 待ってしまう。util-linux の `script` で擬似 TTY を割り当て、isatty を真にして
  # 対話モードで起動させる。/dev/null に typescript を捨て、-q で開始/終了メッセージ
  # を抑止、-e で claude の終了コードをそのまま返す。claude の出力は journal に出る。
  # サーバモード `claude remote-control` を使う。対話モード（`claude --remote-control`）は
  # 人が端末に座る前提で、headless の systemd 常駐だと Remote Control 登録が安定せず
  # アプリ側にセッションが出なかった。サーバモードは端末で待ち受ける常駐専用で、
  # 実機の最小環境（HOME/TERM/PATH のみ）でも接続成功を確認済み。スマホ/Web から
  # このサーバに接続してセッションを作る運用になる。--verbose は接続ログを journal に出す。
  #
  # --spawn=same-dir を明示する。未指定だと初回に spawn モード（same-dir/worktree）の
  # 対話選択プロンプトが出て、headless では答えられず停止するため。same-dir は既定で、
  # 各セッションが同じ作業ディレクトリを共有する。git worktree で分離したいなら worktree。
  #
  # --name にホスト名を渡し、アプリ/Web のセッション一覧での表示名を固定する（rpi5 等）。
  #
  # claude 本体は store パス直指定ではなく system プロファイルの
  # /run/current-system/sw/bin/claude を使う。対話ログイン時の `claude` と同一実体に
  # なり、認証状態（~/.claude）や挙動を確実にそろえられる。
  claudeCmd = "/run/current-system/sw/bin/claude remote-control --spawn=same-dir --name ${config.networking.hostName} --verbose";
  ptyWrapped = "${pkgs.util-linux}/bin/script -q -e -c ${lib.escapeShellArg claudeCmd} /dev/null";

  # 時計が同期されるまで claude の起動を遅らせる ExecStartPre。
  # RTC の無い Pi は起動直後の時計がズレており、その状態で TLS 接続すると
  # 証明書の有効開始日より過去のため CERT_NOT_YET_VALID で失敗する。
  # timesyncd が同期成功時に作る /run/systemd/timesync/synchronized を直接待つ。最大 120 秒。
  waitForTimeSync = pkgs.writeShellScript "wait-for-timesync" ''
    for _ in $(seq 1 120); do
      [ -e /run/systemd/timesync/synchronized ] && exit 0
      sleep 1
    done
    exit 0
  '';
in
{
  # Claude Code をリモート操作モードで常駐させるサービスを定義する。
  # 起動は自動ではなく手動（`systemctl start claude-remote-control`）。一度上げれば
  # systemd 管理下に入るので、起動に使った SSH セッションを切っても止まらず常駐する。
  # 切断・失敗時は上げ直す（Restart=always）。

  options.services.claudeOnBoot = {
    enable = lib.mkEnableOption "claude remote-control（サーバモード）の常駐サービスを定義する（起動は systemctl start で手動）";

    user = lib.mkOption {
      type = lib.types.str;
      default = "nixos";
      description = "サービスを実行するユーザー（認証済みの ~/.claude を持つ）。";
    };

    group = lib.mkOption {
      type = lib.types.str;
      default = "users";
      description = "サービスを実行するグループ。";
    };
  };

  config = lib.mkIf cfg.enable {
    systemd.services.claude-remote-control = {
      description = "Claude Code in remote-control mode";

      # wantedBy を設定しない＝起動時に自動常駐しない。SSH で入ってから
      # `systemctl start claude-remote-control` で手動起動する運用。

      environment = {
        # 認証済みの ~/.claude を参照させる。
        HOME = "/home/${cfg.user}";
        # 擬似 TTY で TUI を出すため端末種別を渡しておく。
        TERM = "xterm-256color";
        # 対話ログインと同じくシステムの全パッケージを PATH に載せ、claude が
        # git/node などのツールを呼べるようにする。
        PATH = lib.mkForce "/run/wrappers/bin:/run/current-system/sw/bin";
      };

      serviceConfig = {
        Type = "simple";
        User = cfg.user;
        Group = cfg.group;
        WorkingDirectory = "/home/${cfg.user}";
        # 時計が同期されるまで待ってから claude を起動する。
        ExecStartPre = waitForTimeSync;
        ExecStart = ptyWrapped;
        # リモート操作を維持したいので、切断・失敗でも上げ直す。
        Restart = "always";
        RestartSec = 10;
      };
    };
  };
}
```
:::

ポイントは **起動は自動ではなく手動** だということです。headless（TTY なし）の環境で boot 時に自動常駐させると Remote Control の登録が安定しなかったため、SSH で入ってから手動で起動する運用にしています。一度 systemd 管理下に入れば、起動に使った SSH セッションを切ってもサーバは止まらず常駐し続けます（`Restart=always`）。

操作はホーム直下に置かれる操作用 Taskfile（`~/Taskfile.yml`）で行います。宣言的に配置される読み取り専用のファイルで、`systemctl` の細かいコマンドを覚えなくても済むようにしてあります。

```shell
$ task start     # 起動して常駐させる（SSH を切っても継続）
$ task status    # 状態を見る
$ task logs      # ログを追う（Ctrl-C で終了）
$ task stop      # 停止する
```

起動後はスマホ／Web のクライアントからこのサーバに接続し、セッションを作って操作します。

:::message
サーバモード（`claude remote-control`）で常駐させている理由、擬似 TTY 経由で起動する理由、起動直後の時刻ズレによる TLS 失敗を避けるため時刻同期を待ってから起動する理由などは、`modules/claude-remote-control-service.nix` のコメントに詳しく書いています。
:::

## AI-DLC ワークフローの導入

同じ操作用 Taskfile には、[AI-DLC Workflows](https://github.com/awslabs/aidlc-workflows) を作業リポジトリへ導入する `setup-aidlc` タスクも入れています。AI-DLC 一式（`aidlc-workflows` の `v2` ブランチ）は起動時の pull でホーム直下に置かれているので、そこから対象リポジトリへ `.claude/` と `aidlc/` をコピーします。

```shell
$ task setup-aidlc DEST=<リポジトリ名>
```

`DEST` はホーム直下にある導入先リポジトリのディレクトリ名です。導入後、Claude 側で `/aidlc --doctor` を実行して確認します。

# 実機への反映（デプロイ）

一度動いている Pi には、イメージを焼き直さなくても設定変更を反映できます。

```console
$ task switch-rpi5 IP=<ip>
```

Pi 5 自身がビルドと適用を行い、Mac は指示を出すだけです（`sudo` のパスワードを聞かれます）。

# まとめ

- Docker を Linux ビルダーにすれば、macOS からでも Pi 5 用 NixOS イメージを再現性よくビルドできる
- 焼く前に SSH 公開鍵を仕込むことで、初回起動後すぐ鍵認証で入れる
- 秘密情報は実機側に置き、store / git には残さない
- Claude Code は自動起動せず、`~/Taskfile.yml` の `task start` で手動常駐させる（切断しても継続）
- AI-DLC は `task setup-aidlc DEST=<repo>` で対象リポジトリへ導入できる
- 設定変更は `task switch-rpi5` で焼き直しなしに反映できる

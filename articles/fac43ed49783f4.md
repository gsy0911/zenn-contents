# はじめに

https://zenn.dev/gsy0911/articles/0a8e0e2156579d

という記事を書いてから毎日Taskfileを使っています。そんなTaskfileの実行をちょっと便利にする方法を紹介します。

# 通常のTaskfile

zennの記事を書く際には以下のような Taskfile.yaml を作成しています。

```yaml: Taskfile.yaml
version: '3'

tasks:
  article:
    desc: create new article
    cmds:
      - npx zenn new:article
```

その上で `$ task article` とすると、`npx zenn new:article`の内容を実行してくれます。

# Task 実行時に引数を与える場合

タスクがシンプルな場合だと全然問題ないですが、Taskfileはいろいろな場合を考慮して、引数を与える場合があります。例えば環境ごとのデプロイのコマンドなどです。

```yaml: Taskfile.yaml
version: '3'

tasks:
  cdk-deploy:
    desc: deploy cdk
    dir: infrastructure
    cmds:
      - cdk deploy --context env={{.env}}
```

このコマンドは`$ env=dev task cdk-deploy`のように実行します。与える引数が1つだけでenvのようにわかりやすいものだといいのですが複数個ある場合には途端に入力が大変になります。

簡単な回避策としては


```diff yaml: Taskfile.yaml
version: '3'

tasks:
+ default:
+   cmds:
+     - task -l

  cdk-deploy:
-   desc: deploy cdk
+   desc: deploy cdk. example $ env=(dev|stg|prod) task cdk-deploy
    dir: infrastructure
    cmds:
      - cdk deploy --context env={{.env}}
```

のようにdefaultのコマンドを付与した上で、`$ task | grep cdk-deploy`などとするとコマンド例とともに見えます。

# Task 実行時に引数を制限する

また、Taskfile の機能で引数の入力を制限することもできます。

```diff yaml: Taskfile.yaml
version: '3'

tasks:
  default:
    cmds:
      - task -l

  cdk-deploy:
    desc: deploy cdk. example $ env=(dev|stg|prod) task cdk-deploy
    dir: infrastructure
    cmds:
      - cdk deploy --context env={{.env}}
+   requires:
+     vars: [env]
```

こうすると、引数に env の入力を求められます。
![](/images/taskfile_bindkey/taskfile_bindkey_06.png =600x)
*envが必須になっている*


また、`enum` を指定するとenum以外の値を入力するとエラーにすることもできます。

```diff yaml:Taskfile.yaml
version: '3'

tasks:
  default:
    cmds:
      - task -l

  cdk-deploy:
    desc: deploy cdk. example $ env=(dev|stg|prod) task cdk-deploy
    dir: infrastructure
    cmds:
      - cdk deploy --context env={{.env}}
+   requires:
+     vars:
+       - name: env
+         enum: [dev, stg, prod]
```

こうすると、enum 以外の値を入力できなくなります。

![](/images/taskfile_bindkey/taskfile_bindkey_07.png =600x)
*env=(dev|stg|prod)のいずれかのみ許容となっている*


# Task 実行時に引数とコマンドを自動取得する

ここからが本題です。Taskfileを実行する際に解決したい面倒なポイントは次の2点です。

1. taskのコマンドの入力が煩雑
2. task実行時の引数の入力が煩雑

1についてはあいまい検索で対象のコマンドを見つけるようにし、2については`taskfile.yaml`をパースして引数を特定します。

## 1. あいまい検索について

https://formulae.brew.sh/formula/fzf
を使います。

macの場合にはbrewで次のコマンドでインストール可能です。
```shell
$ brew install fzf
```

インストール後に

```shell
$ task | grep -v "Available tasks for" | fzf
```
と実行すると、あいまい検索の結果と絞り込みができるようになります

![](/images/taskfile_bindkey/taskfile_bindkey_02.png =600x)
*（再掲）あいまい検索画面*

![](/images/taskfile_bindkey/taskfile_bindkey_03.png =600x)
*（再掲）曖昧検索での絞り込み*


## 2. taskfileをパースする

https://github.com/gsy0911/taskfile-parser

taskfile.yamlをパースするために、`taskfile-parser`というツールを作成しました^[参考 https://zenn.dev/karaage0703/articles/3ce79805245fef]。

次のような`Taskfile.yaml`がある状態で

```yaml: Taskfile.yaml
version: '3'

tasks:
  default:
    cmds:
      - task -l

  cdk-deploy:
    desc: deploy cdk. example $ env=(dev|stg|prod) task cdk-deploy
    dir: infrastructure
    cmds:
      - cdk deploy --context env={{.env}}
```

次のコマンドを実行すると

```shell
$ uvx --from git+https://github.com/gsy0911/taskfile-parser parser \
  --pwd $(pwd) \
  --taskfile-task-name cdk-deploy
```

次のような結果が得られます。

```shell
env=dev|stg|prod task cdk-deploy
```

この`fzf`と`taskfile-parser`を使ってTaskfileをちょっと使いやすくします。


## zle を使ってすぐに呼び出せるようにする
ZLE (Zsh Line Editor) は、zsh の標準機能で、コマンドライン入力を自在に制御するための仕組みです。通常はカーソル移動や履歴検索などに使われますが、自作の関数（ウィジェット）を登録して特定のキーに割り当てることで、コマンドラインへの文字入力や編集をプログラムから操作できるようになります。

`taskfile-parser` でコマンドの結果を得られたとしても、長いコマンドを毎回手入力していたら本末転倒です。そこで、この ZLE を使って「タスクを選択したら、自動的に引数入力用のテンプレートがコマンドラインに入力される」仕組みを作ります。


```zsh: ~/.zshrc
# Setup colors
autoload -Uz colors && colors

# 1) Prefix 用キーマップを作る
# udk_zsh:= user-defined-kymap zsh
bindkey -N udk_zsh

# 2) Prefix に入るウィジェット
function zle-enter-prefix() {
  zle -K udk_zsh
  # ステータスラインにメッセージを表示 (意図してprintfを使っている)
  printf "\n$Red + ZSH$Rst:\tt: task"
}
zle -N zle-enter-prefix

# 3) Cancel widget
# Esc でキャンセルして main に戻る
function prefix-cancel() {
  zle -K main
  zle -M "" 
}
zle -N prefix-cancel
bindkey -M udk_zsh '\e' prefix-cancel

# 4) Prefix キー（例: Ctrl-w）
bindkey '^w' zle-enter-prefix


# fzf-task-command-copy
function tl() {
    # 色の定義
    local Grn=$'\e[32m'
    local Rst=$'\e[m'

    # zle -I # 外部コマンド実行前に画面をクリア
    
    # taskコマンドの出力を取得
    local src=$(task | grep -v "Available tasks for" | fzf)
    
    if [ -z "$src" ]; then
        # キャンセルされた場合
        zle -K main
        zle redisplay
        return
    fi

    local selected=$(echo $src | cut -d' ' -f2)
    local selectedCommand=${selected%?}
    
    if [ -n "$selectedCommand" ]; then
        # クリップボードにコピー
        echo -n "task $selectedCommand" | pbcopy
        
        # Descriptionの抽出と表示
        local desc=$(echo $src | awk -F'[:*]' '{print $3}' | sed 's/^ *//')
        # 意図してprintfを使っている（メッセージを消したくないため）
        printf "\n$Grn * DESC:$Rst\t$desc\n\n"

        # taskfile-parserを使って実際のコマンドを展開
        local command=$(uvx --from git+https://github.com/gsy0911/taskfile-parser parser --pwd $(pwd) --taskfile-task-name $selectedCommand)
        BUFFER=$command
    fi
    
    zle -K main
}
zle -N tl
bindkey -M udk_zsh 't' tl
```

を追記します。
その上で、`control + w`を押下しすると次の状態になります。

![](/images/taskfile_bindkey/taskfile_bindkey_01.png =600x)


その後に`t`を押下するとuvが実行されて、自動的にコマンドが入力される状態になります。

![](/images/taskfile_bindkey/taskfile_bindkey_02.png =600x)

するとあいまい検索の画面になり、

![](/images/taskfile_bindkey/taskfile_bindkey_03.png =600x)

絞り込んだ後に、Enterキーを押下すると

![](/images/taskfile_bindkey/taskfile_bindkey_04.png =600x)

taskfileの引数とコマンドが入力された状態になります。

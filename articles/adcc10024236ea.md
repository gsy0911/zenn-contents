# はじめに

ある日、以下の記事を見つけてzellijというtmuxに似たターミナルマルチプレクサがあることを知りました。
https://zenn.dev/hirokitakamura/articles/zellij-complete-guide

WezTerm のworkspace機能やタブ機能で日々の開発では事足りるのですが、git worktreeを使うときにzellijを使うとより簡単に管理できるようになりました。本記事ではその方法を紹介します。特にAIに並列実装させるときには私にとって必須の仕組みです。AIを使わない通常の開発シーンでも使えます。

# zellijとは

paneやtabの操作方法がわかりやすいのと、コマンドがわからない場合でも下部に表示されており、いつでも参照できます。もちろん、zellijの操作に慣れた場合にはこれらの補助機能は非表示にすることができます。

ロック機能もあって便利です。特にneovimなどを使ってるとキーバインドが競合してしまうことがあるのですが、その心配が全くありません。

zellijにはlayout機能というのがあります。起動時にpaneの分割・名前設定などを指定できるものです。これを使ってIDEっぽく使う事も可能です。ただ、今回はIDEなどではなく起動時にタブを指定して起動する方法を紹介します。


## 私の従来のWezTermでの開発方法

従来はWezTermのワークスペースとタブ機能を使って開発していました。ペイン分割については、表示領域が狭くなるので使っていないです。ワークスペースというのは複数のタブを束ねた機能のことで、今まではワークスペースを1つのリポジトリや関連プロジェクトとしてまとめて開いていました。


プロジェクトAのリポジトリRepo-Aに関して、以下の4つのタブが存在し
- `docker compose up`を起動するタブ
- フロントエンドを起動するタブ
- 適宜何かしらのコマンドを叩くタブ  
- copilotを開くタブ

それらを1つのワークスペースworkspace-Aで管理する、という形です。異なるプロジェクトBはworkspace-Bで開いて随時切り替えると言った形です。

こうすることで、見えているタブや内容はそれぞれのプロジェクトで閉じた状態にできます。

## 困ったこと

これまでの開発方法では特に困ることはありませんでした。理由としては、プロジェクトについては1つのブランチのみで完結していたためです。それがgit worktreeを導入することによって、同じプロジェクトでも異なるブランチの状態が混在するようになってしまいました。

## zshのショートカット

毎回`$ zellij -s name -n dev` などと打つのは大変なので zsh の関数を作成しています。デフォルトでは起動したディレクトリの名前がzellijのセッションの名前になります。

```zsh: ~/.zshrc

```

ポイントとして、zellijのセッションの名前にgitのリポジトリの名前を付与していることです。こうすることでどのセッションが対応しているのかがすぐに判別可能です。
